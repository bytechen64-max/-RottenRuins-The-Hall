# 绯红誓约 · 起誓（蹲下右键蓄力 → 巨型法阵）

> 需求原文（要点）：蹲下 + 右键格挡开始蓄力；蓄力期间玩家身下出现"渐渐扩散运动"
> 的法阵（要用部分 tick 插值）；蓄满后在**视线所指的方向**释放一个**巨型法阵**，
> 持续 **20 秒**；法阵中心是立方体着色器渲染的**立体内容**；法阵照耀的 **y 轴区域**
> 覆盖上方的**方块扭曲**着色器特效；法阵周期性发出**扩散波**；结束时**自天而降**
> 一段 Strand+Muzzle 渲染内容，并最终释放一次**巨量的地形破坏**；
> 法阵写成**独立的技能实体**，与其它 skill 实体一致。

---

## 一、怎么用（玩家视角）

| 操作 | 结果 |
|---|---|
| 右键（**不蹲**） | 照旧：1.8 式举剑格挡（与改动前完全一致） |
| **蹲下 + 右键** | 举剑格挡 **并且** 在脚下起誓 —— 身下浮出蓄力法阵 |
| 蓄力 3 秒（60 tick）自动完成 | 沿视线选点，在落点展开巨型法阵（半径 14 格，持续 20 秒） |
| 蓄力未满就松开右键 | 法阵直接散掉，**不消耗冷却**（经典"按住蓄力"手感） |
| 冷却 30 秒 | 只锁"起誓"，**不锁右键** —— 冷却期间照样能格挡 |

调试指令（需要 OP / 权限 2）：

```
/crimsonvow field [radius] [maxAge]   # 直接在视线落点展开法阵（跳过蓄力）
/crimsonvow charge                    # 在脚下起一个蓄力法阵（纯视觉）
/crimsonvow ready                     # 清掉起誓冷却
```

> `/crimsonvow field 14 120` 是最常用的一条：`maxAge` 压到 120（6 秒）之后，
> 3 秒就能看到终末那一段，不用每次等 17 秒。

## 二、时间线

```
t=0            蹲下右键 → CrimsonVow.onBlockStart
               └ 服务端生成 CrimsonVowChargeEntity（跟着玩家走）

0 → 60t        蓄力（3 秒）
               ├ 身下法阵：同一枚"血月誓约印"的缩小版 —— 外双环 + 16 根短刺
               │  + 48 刻度 + 24 格笔画符文 + 8 根誓约刃 + 内封印环 + 中心四臂十字；
               │  三圈相位错开地向外推；半径 0.85 → 4.6 格
               ├ 阵心升起一根立柱，高度与亮度随蓄力增长
               ├ 最后 15% 开始"过载"：外环与刃高频抖动
               └ 客户端：举剑姿态随蓄力前推、压低（CrimsonVowBlockRig）

t=60           蓄满 → 实体自己选点并展开 CrimsonVowFieldEntity
               ├ 眼睛 → 视线方向射线 42 格，打中就用命中点，打不中就用射线末端
               ├ 落点再向下扫一次地面（避免法阵挂在墙中间）
               └ 冲击环 + 音效 + 粒子 + 相机抖动 + FOV 冲击

0 → 20s        巨型法阵（400 tick）
               ├ 阵面        血月誓约印：外双环 + 奔跑亮弧 → 96 枚刻度 →
               │  36 格笔画符文 → 12 根誓约刃 + 轨道环 → 内封印环（框住立方体核心）
               │  → 中心三臂慢旋；外围 24 根短刺
               ├ 0–10t      展开
               ├ 每 24t      一圈扩散波（**只有判定 + 阵面脉冲环**，不再生成冲击波实体）
               ├ 中心        液态铬（世界空间光线步进：球/环/方块/八面体熔融 + 四颗卫星球）
               ├ 上方 15 格  y 轴区域内的方块扭曲（随高度平方衰减）
               └ 最后 70t    终末（见下）

终末 70t（3.5 秒）拆成三拍 —— 这是"张力"的结构：

0 → 30t        ① 预警（1.5 秒）
               ├ 天顶裂口张开（`uMode=4` 的水平圆盘，半径 2.1× 法阵）
               ├ 幽灵柱（`uLayer=2`）从裂口往下"灌"到 28% 高，不触地
               ├ 阵面三圈**向内收** —— 与前面 20 秒的外扩波刻意反向
               ├ 每 5t 一次渐强的镜头抖动 + 一路上爬的音调
               └ 最后 5t 一次 −2.5° 的 FOV（画面轻微压紧，给落下那一下留对比）

30 → 44t       ② 光柱落下（14 tick / 0.7 秒，1.45 次幂缓入）
               ├ 三层同心柱：软光晕（0.40 半径）/ 主体（0.245）/ 白热核（0.075）
               ├ 每层柱底各补一个枪尖锥（堵住开口圆筒 + 给出方向）
               └ 主体上是三条绕柱电弧 + 一道向下扫的环

t=44           ③ 触地：全阵白闪 + 白热冲击环从阵心扩到阵沿 + 爆闪
               + 冲击环实体 + 粒子 + 音效 + 满档抖动 / FOV +7°

44 → 70t       ④ 余波：光柱**从下往上烧断**（不是两端一起缩），
               地面留一圈灼痕；地形由内向外分帧破坏
```

**冲击波实体只在两处出现**：法阵展开（`CrimsonVowChargeEntity#release`）
与终末触地（`enterImpact`）。周期波只留法阵自己的脉冲环 —— 20 秒里连开
16 个全屏折射球壳只会互相盖掉，还会把真正该被记住的那两下稀释掉。

## 三、代码结构

### 服务端（两个技能实体）

| 文件 | 职责 |
|---|---|
| `overworld/…/skills/CrimsonVowChargeEntity.java` | 蓄力法阵：跟随玩家、推进进度、射线选点、生成巨型法阵 |
| `overworld/…/skills/CrimsonVowFieldEntity.java` | 巨型法阵：扩散波、伤害、终末光柱、**分帧地形破坏** |

**为什么蓄力逻辑在实体里、不在物品类里**：物品类只负责"开启"。
选点、跟随、进度同步、放技能是一条完整的时间线，收在实体里之后
"同一套蓄力以后可以被别的剑复用"，而 `CrimsonVow` 不用同时承担四件事。

## 三·补、第二轮实机反馈后的三处修正

### 1. 冲击波实体用得太密 → 只留两次

原来每 24 tick 起一个 `ShockwaveEntity`，20 秒共 16 个。它们互相叠加、
互相盖掉，画面变成持续的糊，而且把"展开"和"终末"这两下稀释掉了。
现在只在**展开**和**触地**各一次（见上面的时间线）。

### 2. 中间的立体渲染看不见 —— 一个真正的 bug

**症状**：法阵中心的立方体在任何情况下都不出现。

**根因**：离屏复现（`build/shader-preview/CubePreview.java`，照抄
`drawCube` 的几何、GL 状态与全部 uniform）测出：

```
cube_nodepth.png      非黑像素=29523/172800
cube_depth_far.png    非黑像素=    0/172800      ← 背景 60 格外，本不该遮挡
cube_depth_near.png   非黑像素=    0/172800
```

也就是说 `uHasDepth = 1` 时**整块被 discard 干净**。问题出在深度比较用的
线性化公式：它反解视空间 z 时分子取了 `ProjMat[3][2] - ProjMat[2][2]`，
而标准 GL 透视矩阵（MC 用的正是 `Matrix4f.setPerspective(fov, aspect, 0.05, depthFar)`）
满足的是

```
ndcZ = -(ProjMat[2][2] + ProjMat[3][2] / z_view)
```

两式相差一个 `|(B-A)/B| ≈ 2·far` 量级的系数 —— `zScene` 被放大近一个数量级，
判定永远不成立。

**修法**：不再反解，改成**正推** —— 把命中点的视空间 z 用投影矩阵算出它
本该写进深度缓冲的值，再与深度纹理直接比较。一次乘加，没有约定风险，
也不依赖 far 的量级。修完实测：

```
cube_depth_far.png    非黑像素=29523/172800   ← 与 no-depth 完全一致
cube_depth_near.png   非黑像素=    0/172800   ← 前面确实有东西时仍然正确遮挡
```

> ⚠️ 同一个公式也出现在现役的 `rendertype_shockwave.fsh` 里。若那边
> `uHasDepth` 实际为 1，冲击波的折射会被整块 discard —— 值得单独核一下
> （本次没有改动那个文件）。`rendertype_crimson_warp` 已一并改成正推。

### 3. 立方体"看着不像那个着色器" → 换成 DF0，并补上结构

**根因（也是实测出来的）**：`#define DF2` 那支是一个 8 次范数的超椭球
（几乎就是个圆角方块）被一圈细环挖了一刀。它有两个致命问题：

- 正脸几乎是平面 ⇒ 法线不变 ⇒ 漫反射是常数 ⇒ 一块死色；
- 那条环大多落在背面/侧面，而"全光线最小环面距离"在可见表面上几乎恒为 0，
  于是 `1/sqrt(g_gd)` 变成一个**处处相同还被 clamp 到上限的常数项**，
  把整块面彻底拍平。

**修法**：
- 表面图案改用**命中点**的环面距离（`ogdHit`），而不是全光线最小值；
- 补上移动补光、世界坐标表面图案、边缘菲涅尔；
- 曝光压到 0.34 —— 那些"往 1 以上加"的自发光项不压的话，
  `aces_approx` 会把整块面推到饱和，等于把上面所有结构再拍平一次；
- **默认改用 `#define DF0`**（"一个大球被切成很多方块"），原作者在文件里
  本来就写了 "Try different approximations of 'cubes' by changing between DF0-DF7"。
  想看回 DF2：把 `rendertype_crimson_cube.fsh` 里那两行 `#define` 对调即可。

**第三轮（实机截图）又修了两处：**

- **格子密度**。原版 FLAIR 取 `bsz = 2*sz/(3-1) = 20`，也就是整个球里<b>只切出
  2×2×2 格</b>。那在 Shadertoy 里（物体只占屏幕一小块、距离 76 单位）没问题，
  搬到世界空间、玩家走到 5~10 格外时，看到的是"中间一个大方块 + 六个方向各伸出
  一截"的十字形色块 —— 截图确认过。现在用 `#define GRID 7.0`，球被切成 7×7×7，
  每个小方块约 1.4 格，近距离一眼就是"一堆方块组成的球"。
- **DF0 下那两项自发光会退化成常数**。DF0 的 `ogd` 是外球壳距离，在表面上恒为 0，
  于是 `1/sqrt(g_gd)` 与 `exp(-|ogdHit|)` 都变成"处处相同、还被 clamp 到上限"的
  常数项，把整块面拍成一块发白的死色（截图里那个白色十字就是它）。
  现在这两项用 `#if !defined(DF0)` 圈起来，DF0 只留一层很淡的体辉光，
  结构交给真实几何 + 光照 / 移动补光 / 菲涅尔 / AO。
  曝光也按变体分开：DF0 用 0.95，DF2 仍然 0.34（它必须压，理由见上）。
- 顺便补了一条防护：相机落在<b>实体内部</b>（DF < 0）时直接 discard ——
  包围盒有 15 格高，玩家走进阵心就会站在盒子里，那时整条光线起点已经在
  "已命中"状态，步进跑不动、法线退化成 0，画面上是一整块糊屏的死色。

### 4. 落下的激光"不像 Strand" → 撤掉世界空间光柱，并把它从 GUI 覆盖层搬进世界 pass

原来除了一层全屏 Strand+Muzzle 叠层，世界空间里还画了一根圆柱
（`rendertype_crimson_sigil` 的 `uMode=2`）。实机反馈很直接：那根柱子和
Strand 内容毫无关系 —— 它只是一根会发光的圆管，而 Strand 的辨识度全在
"六条横贯屏幕的彩色正弦光带 + 枪口爆闪"上，那本来就是屏幕空间的东西。

**第一版把叠层挂在 `RenderGuiOverlayEvent.Post`（HOTBAR）上，实机反馈是整段
叠层根本看不见，而日志里查不出原因**（世界侧那根柱子又已经撤了，于是终末什么
都不剩）。那条路有三个额外前提：HUD 必须渲染、GUI 缩放必须正常、事件必须按预期
触发。现在改成在**世界 pass 的末尾**直接画：自己临时把投影换成像素空间正交、
画一个整屏四边形、画完立刻还原。不依赖任何 GUI 事件，按 F1 也照样在，
而且与法阵 / 立方体 / 扭曲柱在同一个渲染入口里，出问题一定看得见。

另外把"法阵在相机背后"那一路从"不更新"改成"退回屏幕中央偏上的默认落点" ——
否则玩家一转头，整段终末就什么都不剩了。

### 5. 光柱"没有张力" —— 三个叠加的根因（这一轮的主改动）

实机反馈：激光落下没有张力、不华丽、不够有冲击力。查下来这不是"参数不够猛"，
而是三层问题叠在一起。

#### 5.1 真 bug：逐顶点高度从来没进过片元

旧版把"这一帧柱子的长度"写进 `Color.r` 当作高度用。`POSITION_COLOR_NORMAL`
的 Color 是 **4 个 ubyte**：`34` 写进去是 `34 * 255 = 8670`，截成低 8 位
`222`，读回来 `0.8706`。于是**整根柱子所有顶点的高度都是 0.87**。

离屏复现（把 `vertexColor.r` 直接输出成颜色）：整根柱子是同一个灰值。

后果是连锁的，而且全都不报错：

- `hN` 恒 0.87 → 六条螺旋只剩最上面一条，其余全被 `if (v0 <= 1.06)` 挡掉；
- 柱头光斑 `exp(-60/5) ≈ 0` → 没有"头"；
- 枪口爆闪的局部坐标 `dH ≈ 250` → 永远落在 `d = 0`；
- 顶点波动里的 `hn = Color.r / 自己` 恒为 1 → 侧影是一条直筒。

所以画面上只剩"柱身常数 + 顶端余晖"两项 —— 一根均匀发亮的半透明塑料管。

**修法**：高度改走 `Normal.x`（3 个 **float**，0..100+ 格都精确），vsh 转发成
`vHeight`，片元用它算 `rel / hN`；`Color.r` 在光柱里留 0。

#### 5.2 观感：菲涅尔把光柱画成了玻璃管

柱面法线在屏幕两侧与视线近乎垂直、在正中近乎平行，所以
`1 - |dot(v, n)|` 是**两边亮、中间暗** —— 那正是"玻璃筒高光边"的读法。
能量柱必须反过来：正对镜头的那部分最亮（视线上累积的发光介质最多）。

现在用 `facing = pow(1 - |dot|, 1.35)` 当主权重，配三层同心柱：

| 层 | 半径 / 法阵半径 | 亮度 | 作用 |
|---|---|---|---|
| 软光晕 | 0.40 | 0.55 | 大而淡的一团，外沿波动最大 |
| 主体 | 0.245 | 1.0 | 三条绕柱电弧 + 向下扫的环 |
| 白热核 | 0.075 | 1.0 | 只有主体 1/3 粗的近白细柱，读作"能量密度" |

三层都是同一根圆柱、同一个 program，只差 uniform。柱底每层各补一个
**枪尖锥**（半径 = 该层半径），否则开口圆筒从下往上看就是一个"亮碗"。

#### 5.3 结构：0.35 秒的落下没有"预告"

旧版从 `enterFinale` 到触地只有 7 tick，等于"亮了一下、地上炸了"。
现在拆成三拍，并把总时长压进原来的 `FINALE_TICKS = 70`：

- `WARNING_TICKS = 30`（1.5 秒预告）：天顶裂口 + 幽灵柱下灌 + 阵面三圈内收 +
  每 5 tick 一次渐强抖动 / 爬升音调 + 落下前一次 −2.5° FOV；
- `BEAM_FALL_TICKS = 7 → 14`（0.7 秒）：仍是从 70 格高砸下来（5 格/tick），
  但现在眼睛能跟住那个"头"；几何用 1.45 次幂缓入，前几帧"悬"一下；
- 触地：全阵白闪（0.3 秒）+ 从阵心扩到阵沿的白热环 + 光柱从下往上烧断。

> 预告的可见性是有取舍的：站在法阵边上（≤ 30 格）平视时，天顶裂口在视野
> 上方之外，玩家真正看到的是**地上的内收环 + 那条往下灌的幽灵柱**；
> 裂口是抬头或远距离（第三人称 / 旁观）时的奖励。所以预告不能只靠裂口。

#### 5.4 新 uniform / 新常量

| 名字 | 含义 |
|---|---|
| `uWarn` | 0..1 预警进度（0 = 未开始，1 = 光柱已落） |
| `uImpactAge` | 触地后的**秒数**；未触地为 −1（直接拿它当"有没有触地"的判据） |
| `uBeamHead` | 光柱前缘（柱底）的世界 Y |
| `uBeamSpan` | 可见段长度（格） |
| `uLayer` | 0 主体 / 1 白热核 / 2 幽灵柱 / 3 枪尖 |
| `uBeamHeight` | **删除**（语义与 `uBeamSpan` 重叠，留着只会再骗一次） |

`vHeight`（世界 Y）从 .vsh 以 `out float` 传给片元 —— 它是这一轮所有图案
能"钉在世界尺度上"的前提。

### 6. 阵心的"立方体"太丑 → 换成血晶

实机反馈：中间悬浮的立方体有点丑。

**它为什么丑**：DF0 是"一颗球被切成 7×7×7 个圆角方块"。离屏里（物体占屏
几十到几百像素、距离固定）它挺清楚；但实机里核心只有 5 格见方、玩家在 20~40
格外，它只剩屏幕上几十像素 —— 圆角 + 7 格密度糊成一片，读出来是一团发涨的
软糖：没有棱、没有方向，也没有"这里有个东西"的剪影。

**换成什么**：一颗**血晶**（八棱柱身 + 上下尖），外加三块环绕碎晶。

| 旧（方块球） | 新（血晶） |
|---|---|
| 圆角 → 没有剪影 | 竖直棱 + 尖 → 远远就能读出"一颗竖着的晶体" |
| 所有面亮度接近 | 平面切面 + 逐面法线 → 一个面亮、邻面暗 |
| 表面是一层格子花纹 | 棱线发光（`gemEdgeDist`）+ 芯光（内部球） |
| 与"誓约"没有关系 | 血晶 = 誓约的凝结；终末被光柱抽走时也读得通 |

**实现要点**（都在 `rendertype_crimson_cube.fsh`）：

- 形状 = 24 个半空间求交（8 条竖棱 + 8 个上斜面 + 8 个下斜面）。凸多面体的
  `max()` 就是精确 SDF，步进不会穿模；
- `gemEdgeDist()` 取 24 个平面距离的**前两大**，第二个就是"离最近的另一面
  多远"，取指数得到一条贴着棱的亮线 —— 这是"宝石感"最省事也最有效的一笔；
- 芯：一个**不参与形状**的球，从内部把朝向它的面照亮（解析补光，不是折射）；
- 三块碎晶绕主晶体公转，`|r − 轨道| < 5` 早退，避免 SDF 开销翻倍；
- 原来的方块球 / 缠绕环保留成 `#define DF0 / DF2`，把顶部三行对调即可回看。

**离屏踩到的两个坑**（记下来免得再踩）：

1. **双锥不行**。第一版是六棱双锥：玩家站着往上看阵心（低机位）时，正对
   镜头的那一面又大又平，剪影是一块斜放的平行四边形 —— 比方块球更像"一块板"。
   改成"柱身 + 尖"、棱数 6 → 8 之后，任何方位都能露出 2~3 个切面。
2. **染色要减半**。紫粉渐变是乘性的，0.70 的强度会把切面的明暗差全部染平，
   又回到"一团淡粉"；晶体分支用 0.48，曝光 0.62。

| 量 | 位置 | 现值 |
|---|---|---|
| 晶核形状 | `#define DF_CHROME`（第 8 节；下表是第 6 节血晶的历史值） | 液态铬 morph |
| 主晶体尺寸 | `CRYSTAL_R / CRYSTAL_HB / CRYSTAL_H`（DF 单位） | 11 / 12 / 22（约 2.7 格宽 × 5.4 格高） |
| 碎晶 | `SHARD_*` | 3 块，轨道 17，R 2.4 / 尖 6 |
| 棱线亮度 | `gemEdgeDist` 那条 `* 4.6` | 4.6 |
| 芯光亮度 | 晶体分支 `core * 1.15` | 1.15 |

### 7. 屏幕抖动：画面平移，而不是再转一次相机

原来这一招只有"相机角度抖动"（`VerdictCameraEffects`：±1.35° 的俯仰 / 偏航 /
滚转 + FOV 冲击）。它给的是"镜头被撞了一下"，但砸地那一下还缺**重量** ——
于是补了一层**投影矩阵的 NDC 平移**：整幅已渲染的画面平移十几个像素，
相机不转、准星不动、透视关系不变。

两者是叠加关系，不是替换：

| | 相机角度抖动（已有） | 屏幕抖动（新增） |
|---|---|---|
| 改什么 | `ViewportEvent.ComputeCameraAngles` 的 pitch/yaw/roll | `getProjectionMatrix` 的 m30/m31 |
| 画面表现 | 世界绕镜头转，近处位移大 → 有透视变化 | 整幅画面平移 → 只读"重量" |
| 对瞄准 | 会真的偏（±1.35°） | 完全不影响（准星不动） |

**实现**

- `client/rend/ScreenShake.java`：触发 + 包络 + 偏移。包络
  `env = (1 - e^(-age·55)) · e^(-age·9)` —— 约 20ms 到位、0.5 秒收干净。
  横向扰动是两个互质频率叠加，单频会读成"节拍器在摆"。
  偏移写成 **f(时间) 的纯函数**：同一帧里 `getProjectionMatrix` 会被调用多次
  （世界 / 手持物），状态式写法会让第二次调用拿到推进过的值、画面跳一下。
- `mixin/ScreenShakeMixin.java`：在 `GameRenderer#getProjectionMatrix(double)`
  的 RETURN 处左乘一个只含 `m30/m31` 的平移矩阵（`clip.x += dx·w` ⇒ NDC 平移 dx，
  与深度无关）。HUD / 准星 / GUI 走正交矩阵，完全不受影响；地形 / 实体 /
  自发光特效 / 光影包回放会一起平移。
  ⚠️ 用"新建矩阵再左乘"而不是原地改投影：万一哪天原版把投影缓存复用，
  原地加会**每帧累加**、画面越飘越远。
- 触发点：`CrimsonVowFieldRenderHandler` 抓 `PHASE_IMPACT` 的**跳变**
  （客户端本来就有这个同步字段，不需要新增网络包），强度按到相机的距离
  衰减（`1 - d/64`，留 0.2 的底）。
- 顺带修了旁观者：旧版 `enterImpact` 只在"施法者已经走了"时才遍历附近玩家，
  于是队友看着你砸下来、画面纹丝不动。现在半径内的所有玩家都 `shakeNear(0.85)`，
  施法者自己仍是 1.0 + FOV。

| 量 | 位置 | 现值 |
|---|---|---|
| 屏幕抖动幅度 | `ScreenShake.NDC_PER_STRENGTH` | 0.020 NDC（≈11 px @1080p 峰值） |
| 抖动时长 | `DURATION` / `DECAY` / `ATTACK` | 0.6 s 上限 / 9 每秒 / 55 每秒 |
| 触发强度 | `CrimsonVowFieldRenderHandler.updateScreenShake` | `0.20 + 0.80 · 近距系数` |
| 旁观者相机抖动 | `CrimsonVowFieldEntity.enterImpact` | `shakeNear 0.85` |

### 8. 晶核换成"液态铬"（A 档：只换几何 + 材质）

第 6 节那颗血晶仍然有"太素"的问题；这一轮换成一团**液态铬**：
球 → 环 → 圆角方块 → 八面体 之间熔融，四颗 `smin` 融合的卫星球，
表面镜面铬，反射一片只存在于反射里的霓虹 studio。

**A 档的边界**（需求拍板）：只换几何与材质，
- **不**做真实场景反射（省掉 scene copy + 二次光线）；
- **不**把霓虹 studio 画到天上（会和真实天空/地形打架）。

**能直接搬的原因**：这段 Shadertoy 跑的就是我们已经有的一条管线 ——
世界空间 AABB + 逐像素步进 + 深度纹理遮挡。它的 `map()` 就是
`dfeffect()`，要改的只有输入和尺度。

| 项 | Shadertoy | 这里 |
|---|---|---|
| 时间 | `iTime` | `uTime` |
| 相机 | 固定 `ro=(0,0.55,8.6)` | 玩家相机（逐像素世界光线） |
| 尺度 | 物体半径 ≈ 1 | `pDF / CHROME_SCALE` 求距离、再乘回来（精确缩放） |
| 地板 | 真的镜面地板 + 二次 trace | 只在反射里算一块**霓虹网格地板**（不画、不追第二根光线） |
| studio | 画满全屏 | 只进 `chromeEnv()`，作为反射环境 |

**几处离屏调出来的关键点**（否则铬会变成彩色塑料）：

1. **镜子要映"黑"**。只有平滑渐变时，整个球面是一块 `#722868` 的紫。
   加三面随方位转的**遮光旗**（`cos(az*3+0.7)` 压到 0.1 倍）之后才有金属的明暗块。
2. **地板底子要暗、光池要收紧**。玩家从下往上看，看到的主要是下半球，
   也就是全在反射地板：底子一亮就是一层平铺紫雾；改成"暗底 + 中心一团光池 +
   提亮的滚动网格线"，曲面上的反射才是弧形霓虹条纹。
3. **规模**：`CHROME_SCALE = 10.5`（核心半径 1 → 1.2 格，卫星轨道 1.7 → 大约 1.9 格）。
   `smin` 的 k=0.75 与形状常数**一个都不用改** —— 因为我们是在形状自己的尺度上求距离。
4. **步进预算**：SDF 变"软"了（morph + smin），同样步数能走的路更短，
   `MAX_STEPS` 从 64 提到 96（只对 `DF_CHROME` 生效）。
5. **变量名**：`chromeFre` 不能叫 `fre` —— 上面"漫反射 + 主光"那段同作用域里
   已经有一个 `fre`，编译直接报重复声明。

| 量 | 位置 | 现值 |
|---|---|---|
| 形状变体 | 文件顶部 `#define`（在 MAX_STEPS 之前） | `DF_CHROME`；另有 `DF_CRYSTAL` / `DF0` / `DF2` |
| 尺度 | `CHROME_SCALE` | 10.5 |
| morph 周期 | `CHROME_CYCLE` | 25 秒一轮（20 秒技能里变 3 次） |
| 融合半径 | `chromeMap()` 里 `sminq(..., 0.75)` | 0.75（形状尺度） |
| 反射地板 | `-1.45`（形状尺度）+ 网格 `0.5` 格 + 滚动 `0.35` 格/秒 | — |
| 地板光池 | `exp(-dot(fp.xz,fp.xz) * 0.9)` | 收紧的一团 |

### 9. 地面法阵美化（第三轮）：从"随机方块 + 白团"到"血月誓约印"

**离屏基线的问题**（`build/sigil-preview/before/`）一眼能看到三件事：

1. 加法混合的各层系数偏大，中心与外圈都被压成纯白 —— 层次全丢；
2. 符文带是 `step()` 拼的矩形块 + 一条横缝，实机读起来是一圈**随机马赛克**；
3. 巨型法阵中央的六芒星与上一版背板语言重复，而中心又是一坨白。

**改法**（只动 `rendertype_crimson_sigil.fsh` 的 `chargeSigil()` / `fieldSigil()`
两个分支；`uMode = 3` 光柱与 `uMode = 4` 天顶裂口逐行未变）：

- 新抽出一组**笔画零件**：`stroke()`（硬线）、`runeGlyph()`（竖笔 + 横笔 +
  斜笔 + 星点）、`runeBand()`（按角度切格取笔画）、`blade()`（根部宽、尖端收的
  放射刃）。符文从此是"字"，不是方块。
- 两个法阵统一成同一枚**血月誓约印**：
  | 层 | 巨型法阵（uMode=1） | 蓄力法阵（uMode=0） |
  |---|---|---|
  | 外缘 | 双环 + 绕圈奔跑的亮弧 + 24 根短刺 | 双环 + 16 根短刺 |
  | 刻度 | 96 枚（反向转） | 48 枚（反向转） |
  | 符文 | 36 格笔画符文（逐字明灭） | 24 格笔画符文 |
  | 冠刃 | 12 根誓约刃 + 轨道环 + 48 小刻 | 8 根誓约刃（随蓄力变长） |
  | 内圈 | 内封印环 r=0.30 + 24 刻 + 8 短刺 | 内封印环 + 四臂十字 + 亮核 |
  | 中心 | 三臂慢旋（留给立方体核心） | 十字星（蓄力能量的落点） |
  | 动态 | 余烬外漂 / 扩散波 / 终末三圈内收 / 触地白闪 | 三圈外扩波 / 过载抖动 |
- **治过曝**：两个函数的末尾都过一遍软压缩 `col = col / (1 + col * k)`
  （k = 0.45 / 0.50）。加法混合的峰值不再被削成纯白，外圈 / 符文 / 刃 / 波
  四个层次才分得开。
- **扩散波**加了"波前刻度闪 + 尾随回声"，并用 `smoothstep(0.045, 0.130, rr)`
  把起点抬到内封印环之外 —— 否则 `uPulse = 0` 时波正好在圆心，会亮成一块白饼。
- **性能守卫**：每个放射刃循环外都加了径向区间 `if`，不在环带里的片元直接跳过。
  圆盘是 96×6 网格，站在阵内时可能覆盖半屏，这一条能省掉大部分无用的
  `pow/smoothstep`。

**验证**：`tools/shader-preview/sigil.ps1`（实机 6 环 × 96 段圆盘、
POSITION_COLOR_NORMAL 的 u8/i8 量化、加法混合、top / in / out 三个镜头）
出图在 `build/bp-candidates/sigil/out/`；实机图在 `build/bp-ingame-sigil/`。

### 10. 终末光柱重做（第四轮）：vHeight 在实机里恒等于 1.0 —— 先修编码，再改"血誓长矛"

**真 bug：`Normal.x` 不是 float**

`POSITION_COLOR_NORMAL` 的 NORMAL 元素是 **3 个 signed byte、归一化**（1.20.1
`VertexFormatElement` 的 `Type.BYTE`）。`BufferVertexConsumer.normalIntValue()`
的实现是：

```java
(byte) ((int) (Mth.clamp(f, -1.0f, 1.0f) * 127.0f) & 255)
```

也就是说 Java 侧 `emitCylinder` 把**世界 Y（36~70）**写进 `Normal.x` 时，第一
步就被 clamp 成 1.0 → 整根柱子的 `vHeight` 全是 **1.0**。于是：

- `rel = vHeight - uBeamHead` 是一个巨大的负数 → `hN = 0`；
- 前缘光斑 `head = exp(-rel/...) = 1` → **整根柱子都当自己是柱头**；
- 电弧相位、下扫环、tail 淡出全部冻在同一个值上。

实机看到的就是一根**均匀竖条纹的白色塑料管/方尖碑**。此前所有离屏预览台都
把 Normal 当成 3 个 float 来写，所以预览一直"看起来正常"，实机一直难看 ——
两边从未对上过。

**修法（不改顶点格式）**：柱轴在视空间的位置/方向（`uBeamAxisVS` / `uBeamAxisDir`）
Java 每层都已经传了，片元点积即可精确反解世界高度：

```glsl
worldY = uBeamBase + dot(vLocal - uBeamAxisVS, normalize(uBeamAxisDir));
```

`vsh` 里轮廓波动用的 `wy` 也换成同一个反解。蓄力柱（`CrimsonVowChargeRenderer`）
原先没传这两个 uniform，这次补上（否则蓄力柱同样退化成白管）。

**同时重做外观 —— "血誓长矛"**：

| 层 | 做法 |
| --- | --- |
| 解析体积 | 视线（相机在视空间原点）到柱轴的解析距离 `d`，`radial = sqrt(1-(d/r)²)`。中心 1、轮廓 0 —— 边缘自然溶解，彻底替掉 `1-|dot(v,n)|` 启发式（那是"玻璃管"的读法） |
| 主体（uLayer=0） | 向下滚的两层等离子噪声 + 3 条 `pow(sin,26)` 细电弧丝 + 世界尺度下扫脉冲（亮前缘+拖尾）+ 前缘光斑 |
| 白热核（1） | 主体 1/3 粗的近白细柱 + 螺旋灯丝 + 17Hz 电流抖动 + 强前缘 |
| 外光晕（4，新增） | 最宽最淡的一层，只负责"一大团光"；轮廓靠 `radial^2.6` 溶解 |
| 触地飞溅（5，新增） | 柱底宽喇叭口 + 角向火舌，只在触地后 10 tick 内存在 —— 替掉旧版"三层枪尖叠成一支铅笔" |
| 幽灵柱（2） | 同一套体积感，预警段的极淡光通道 |

Java 侧配套：三层 `{4,0,1}`、枪尖按层给不同长度/亮度（外光晕几乎不留尖）、
触地多画一层 uLayer=5 飞溅；蓄力柱补成 halo/body/core 三层 + 柱轴 uniform。

**验证**：新增 `tools/shader-preview/beam.ps1`（`BeamPreview2.java`），它**如实
复现 byte 编码**（Color u8 / Normal i8 + clamp），所以 `-Mode old` 能复现实机那根
难看的白管、`-Mode new` 看到修复后的样子；出图在 `build/beam-preview/before|after/`，
前后对比 `compare_impact.png`。实机图在 `build/bp-ingame-beam/`。

## 四、三个关键设计决定（以及为什么）

### 1. 左右两条渲染路径共用同一份"视基"，而不是各自读 ModelViewMat

所有世界空间特效的契约是：Java 把 `translate(-camera)` 折进 pose，
用 `pose.last().pose()` 变换顶点，于是顶点着色器里的 `Position` 已经是**视空间**坐标。
片元要把"视空间方向"换算回世界方向，需要一个旋转矩阵。

**没有用 Minecraft 自动绑定的 `ModelViewMat`**。原版只在 `applyModelViewMatrix()`
里更新 `RenderSystem.getModelViewMatrix()`，而整条世界渲染路径（地形 / 实体 /
`AFTER_TRIPWIRE_BLOCKS`）都不会调它 —— 它保留的是上一帧 GUI 那趟留下的近单位阵。
本仓库自己的探针日志实测过：

```
[CrimsonVowBackplate] ModelViewMat 与单位阵最大偏差=0.000 ✓ 实测单位阵
```

改成从 `PoseStack` 的法线矩阵直接取旋转部分 R（pose 是刚体变换，法线矩阵就等于 R），
再算出 R 的三行作为 `uViewRight / uViewUp / uViewFwd`：

```
视空间方向 → 世界方向： uViewRight*d.x + uViewUp*d.y + uViewFwd*d.z
世界点     → 视空间：   (dot(uViewRight,d), dot(uViewUp,d), dot(uViewFwd,d))
```

两个换算用的是同一组基，所以不会出现"方向对了、深度错一格"。

### 2. 绘制顺序：扭曲柱必须在所有加法混合之前

```
① 场景拷贝（每帧一次，仅当场上有巨型法阵）
② 所有「扭曲柱」   ← 它是**替换**像素
③ 所有「法阵 / 晶核 / 裂口 / 幽灵柱 / 光柱」 ← 加法混合
```

顺序反了会得到两种很典型的症状：晶核在柱子区域里整个消失（扭曲盖住了它），
或者柱子区域里出现一块没被扭曲的方形（晶核先写进拷贝、又被采样了一次）。

### 3. 地形破坏必须分帧，而且要"由内向外"

半径 11 格、深 10 格的碗形坑约 4000+ 个方块。一 tick 全炸掉的话，
光客户端要收的方块更新包就会让服务端卡住几百毫秒 —— 而"卡一下"会把这一招
最有分量的那一下毁掉。

做法：触地那一 tick **收集**全部目标位置并按**到阵心的水平距离排序**，
之后每 tick 消化 150 个。

排序这一步是整份实现里最关键的一处：由内向外扫，画面就是
"一圈冲击波在啃地面"；按存储顺序（Y 优先）扫，画面上会看到一根根柱子
从上往下塌，像在拆积木。

破坏用 `Level.destroyBlock(pos, false)`（不掉落物：这一招是"抹平"，不是"挖矿"），
并且**跳过硬度 < 0 的方块**（基岩 / 屏障）—— 少了这一句，这一招会把世界底层打穿。

## 六、排查入口

- **法阵完全看不见** → 先看日志有没有 `[Shaders] 加载 rendertype_crimson_* 失败`；
  再确认 `/crimsonvow field` 有没有回执（回执有 = 实体生成了，问题在渲染侧）。
- **扭曲柱没效果** → 它依赖 `ShockwaveRenderer.doSceneCopy()` 那张场景拷贝。
  没有深度纹理（部分光影包把主 RT 的深度换成 renderbuffer）时遮挡判定会退化成
  "不判定"，但折射本身仍然生效。
- **光影包下整块消失** → 检查 `CrimsonVowLateRenderQueue.renderAll()` 是否还被
  `CosmicAfterLevelMixin` 的 TAIL 调用着（漏了那一行，pack 激活时就是"什么都不画"）。
- **卡顿** → 调小 `BLOCKS_PER_TICK`（破坏更慢但更平滑），或调小 `CRATER_RATIO`。
