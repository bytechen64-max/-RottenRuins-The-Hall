# 假死与爆体组件

## 边界

`core/entity/burst/FakeDeathState` 是每个实体独有的状态组件，保存服务端剩余 tick 和客户端起始时间。
负责触发条件、倒计时推进和进度计算；不引用 Minecraft、Forge 或 GeckoLib。

`core/entity/burst/BurstMath` 负责缩放窗口、脉冲数量、阶梯脉冲曲线和逐 tick 确定性抖动。
输入是进度、参数、实体 ID 和世界时间，不读取实体或游戏世界。
从实体基类迁出的计算保留原来的浮点运算顺序、常量和噪声种子公式。

`AbstractRottenEntity` 继续负责连接游戏生命周期：

- 保留原有同步字段及其声明顺序，用 `IS_FAKE_DYING` 作为游戏侧的活动标记；组件不再存一份重复的活动标记。
- 进入假死时，先同步标记，再设置倒计时、恢复生命、触发已有动画，最后调用 `onBurstStart()`。
- 仅服务端在假死期间推进倒计时；正数倒计时归零的那一 tick，先执行 `onBurstEnd()`，再清除标记并移除实体。
- 开始／结束回调、音效、粒子、掉落和伤害来源仍由实体执行。
- 客户端收到标记变化时更新自身起始时间，按世界时间和帧内插值计算表现。

子类仍可使用原有的 `tryFakeDeath()`、`onBurstStart()`、`onBurstEnd()`、渲染模式和参数设置接口。
例如缠绕柱开始爆体时释放抓取物、重磅结束爆体时执行死亡效果的钩子仍留在原来的调用位置。

## 存档与数值约定

`IsFakeDying`、`FakeDeathTimer`、`FakeDeathDuration`、`BurstScaleDuration`、`BurstScaleRate`、
`BurstMaxScale`、`BurstScaleEnabled`、`BurstTwitchAmplitude` 等既有 NBT 键保持不变。
读写 `FakeDeathTimer` 的实现改为访问状态组件，没有新增存档格式。

概率保持旧语义：小于等于 0 表示必定触发；正数按 `nextInt(100) < chance` 判定。
禁用或已在假死时不消耗随机数；概率小于等于 0 时也不消耗随机数。

缩放继续使用每秒脉冲次数、30% 快速鼓起段、smoothstep 回落与 SplitMix64 噪声。
噪声由实体 ID 和世界 tick 决定，不推进游戏随机数；帧内插值只影响进度，不改变同一 tick 的噪声值。
缩放范围、死亡动画缺失时的回退方式、碰撞箱和剔除盒的处理保留原实现。

非正数假死时长、存档里的非正数倒计时仍保留旧行为：不会通过正数倒计时归零路径触发结束。
本次没有将这类边界行为改成自动爆体。

## 本次交付与人工验收

本次只做代码拆分和编译打包；按用户安排，客户端、视觉、存档及实际游戏行为验收由用户进行。
新增组件没有运行时第三方依赖。

建议对照现有生物检查：

1. 单类型及混合类型法术说明、轮盘文字和配色。
2. 普通生物爆体开始、缩放抖动、粒子音效和结束时机。
3. 缠绕柱进入爆体后释放目标；重磅爆体结束后的特有效果。
4. 假死期间保存再加载，剩余时间和原有数据能够继续使用。
5. 关闭缩放、没有 die 动画及各渲染模式下的表现。
