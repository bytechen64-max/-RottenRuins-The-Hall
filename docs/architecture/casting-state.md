# 施法状态与游戏执行

## 职责

- `core/magic/casting/CastingState`：IDLE、CHARGING、CHANNELING 阶段、输入来源、持续时间、按秒计费计时、效果触发计时、蓄力门槛与轮盘容差。只依赖 JDK 和核心数值规则。
- `gameplay/magic/casting/CastSession`：持有独立时序对象，以及法术 ItemStack、槽位、使用手和锁定目标。这些游戏对象不进入核心状态。
- `gameplay/magic/casting/MagicHandle`：玩家会话管理、游戏侧校验、目标解析、事件、扣费、冷却与法术效果执行。
- `StaffBase` 与 `WheelActionPacket`：分别接收原版右键生命周期和轮盘操作，并调用同一个游戏服务。

旧的 `旧物品基类包中的 State` 已移除，MagicHandle 从物品基类包迁往游戏执行层。
仅作旧名转发的 `clientOnServerUsing()` 也已移除，调用方使用 `handleUseStart()`。

## 共用流程

两种入口共同调用 `validateTarget()` 校验法术、主动分类、法杖匹配、冷却、自定义前置和法力预检。
校验结果是一次调用独有的 `CastValidation`，不再通过全局 `lastWheelError` 传递失败原因。
右键入口仍先检查当前手中法杖，轮盘入口仍额外检查旁观者并限定主手。

两种入口的持续会话共同调用 `beginCast()`：

- CHARGE：进入蓄力，不扣蓝、不设置冷却；松手时按当前数值求蓄力完成度并检查最低门槛。
- KEEP：先通过原有 `castNow()` 完成启动，成功后才进入维持并锁定目标。
- IMMEDIATELY：右键直接释放；轮盘通过独立的松手动作调用同一个 `castNow()`。

活动会话不能被另一种输入入口覆盖。来源在进入阶段时明确指定，并在 reset 时复位，避免轮盘标记残留、同一个会话被两种生命周期推进。

## 时序与结算

原版右键继续使用 useItem 提供的 heldTicks；轮盘继续由服务端每 tick 推进自己的 heldTicks。

KEEP 保留两条独立时钟：

1. 每 20 次维持 tick 结算一次按秒费用。
2. 第一次维持 tick 立即触发效果；之后每 interval tick 触发。interval 为 2 时触发 tick 为 1、3、5……；运行中修改 interval 仍使用原有计时方式。

每个维持 tick 仍先处理按秒费用，再处理本次效果的触发费用，最后调用 onKeepTick。
费用不足时结束维持，不先产生免费效果。

CHARGE 保留 `ratio > 0 && ratio >= minimumRatio` 门槛；未达到时不扣蓝、不进冷却。
轮盘松手仍补最多 2 tick 容差，并限制在法术所需蓄力时间以内；计算使用较宽整数中间值，避免极端计时溢出。

实际释放仍按：目标解析 → 可取消事件 → 扣蓝 → 冷却 → 法术效果 → 完成事件。
清理路径仍先 reset 会话，再调用已有的停止回调，避免回调看到已结束的会话仍处于活动阶段。

数值来源、法术效果、已实现的停止回调策略、冷却键、法力来源、视觉参数和网络动作编号未因本轮拆分而调整。
施法会话仍是运行时状态，没有新增存档迁移或网络消息。

## 构建与人工验收

`CastingState` 纳入现有核心依赖检查和空依赖 classpath 独立编译。
本轮按用户安排仅做代码与编译打包，运行验收由用户完成。

建议覆盖右键与轮盘的即时、蓄力和持续三种模式，以及：

- 最低蓄力门槛、提前松手、轮盘 2 tick 容差；
- 维持时按秒／按次扣费、蓝量不足、法术主动停止；
- 换手、切换物品、轮盘取消、登出和重生后的会话清理；
- 轮盘会话中尝试右键，确认不会覆盖或重复推进原会话。
