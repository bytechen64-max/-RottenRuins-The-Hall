# 陨石事件（`/meteorevent`）

> 指令触发 → 玩家视线被拉向天空 → 天顶亮起一颗**十字交叉闪烁的星**，
> 10 秒里越变越大 → 再 10 秒**以同一个十字的形状**砸下来，拖尾拉长、越来越红 →
> 砸中地面，**半径 26 格的碗形坑 + 四道冲击波**，整帧画面被重画成**漫画分镜**（墨线 / 二值 / 网点）。
>
> 贯穿全程的一条硬规则：**天上看到的那颗十字，就是落下来的那个东西**。
> 中途不变球、不变流星 —— 它一直是同一颗十字（见第四节第 4 条）。

---

## 一、怎么用

```
/meteorevent            沿视线选点（最多 100 格）
/meteorevent <distance> 指定选点距离（4~256）
```

需要权限 2。选点规则与 `/crimsonvow field` 一致：沿视线每 0.5 格步进，
碰到第一个非空气方块就落在它上面那一格；一路没碰到就投到视线末端的地表。

> 与已有的 `/meteor` 分开：那是旧的 `MeteoriteEntity`（物理下落、落地即炸），
> 这一条是**三段式天灾事件**。两条指令的生命周期完全不同，合成一条只会
> 让人分不清在测哪个。

---

## 二、时间线

```
t=0          事件实体生成在落点（y 已在地表）
             ├ 天顶一声"开"（END_PORTAL_SPAWN + BEACON_ACTIVATE）
             └ 客户端把视线朝十字星轻拉 2.5 秒（每帧插值，不锁相机）

0 → 200t     ① 显现（10 秒）
             ├ 落点**斜上方**：水平偏 140 格、高 130 格（进入角约 47°），方向随种子
             ├ 十字星：两条正交光条 + 四芒尖 + 过曝核
             ├ 两个互质频率叠加的闪烁；缓慢自转
             └ 视觉半径 2.5 → 16 格（smoothstep 缓入）

200 → 400t   ② 坠落（10 秒）
             ├ **还是那颗十字**（uMode 0），只是越来越大、越来越红
             ├ 沿"起点 → 落点"的斜线砸下来（1-p⁴ 缓入），末速 60 格/秒
             ├ 尺寸涨到 1.8 倍（约 29 格半宽）
             ├ 拖尾 = 斜向圆管（任意轴），头白热 → 尾暗红，湍流条纹向上跑
             ├ **热浪折射**：沿尾迹串 7 块"离屏采样层"（局部圆内偏移采样 + 色散），圆外不碰
             └ 柱半径 0.7 → 3.2 格；颜色随进度白 → 橙 → 暗红

t=400        ③ 砸中
             ├ 落点原地炸开一颗**十字形爆闪**（60 格，14 tick 内炸开淡出）
             ├ 四道冲击环（半径 200 / 120 / 320 / 44 格，速度 180 / 120 / 90 / 60）
             ├ 半径 26 格、中心深 12 格的**碗形坑**（分帧挖，700 方块/tick）
             ├ 半径 44 格内所有活物 160 点伤害 + 击退（施法者豁免）
             ├ 20 个 EXPLOSION_EMITTER + 1600 灵魂火 + 900 熔岩 + 500 末地烛
             ├ 4 个音效（监守者声波炮 / 爆炸 / 重生锚耗尽 / 雷）——按半径反推音量，400 格外仍能听到
             ├ 140 格内所有玩家：镜头抖动 + FOV（施法者满档）
             └ 客户端：屏幕抖动 + 全屏 3bit 红黑爆炸（1.9 秒）

400 → 900t   余波（25 秒；火先熄、尘最后散）
             ├ **蘑菇云**：柱也是 5 圈云团堆的（+ 一根细圆柱芯），冠三层 16+10+6 团，悬垂 12 团
             ├ **扬尘**：单独一趟 alpha 混合（24 团地面环 + 12 团柱脚），画在火**前面**，加法混合画不出暗尘
             ├ 扩散火球：前 70 tick 撑到 46 格，之后 7.5 秒淡出
             ├ 次级爆炸：前 10 秒每 10 tick 在坑里随机位置补一记
             │   （小冲击环 26 格 / 46 格每秒 + 熔岩 + 灵魂火 + 闷响 + 抖动）
             ├ 低频轰鸣：每 45 tick 一声，持续到 22 秒
             ├ 时间顺序：火 12.5→18 秒收完，**扬尘 10→23 秒**才散，最后 2 秒只剩灰
             └ 坑挖完才散（700 方块/tick，约 18 tick）
```

## 四、几个决定（以及为什么）

### 1. 为什么不复用 MeteoriteEntity 的爆炸（改过一次）

第一版是"落点上方生成一颗 `MeteoriteEntity`，让它自己 `doImpact()`"——
省事，但实机反馈很明确：**那是"普通陨石"的演出**，范围小、形状是线框
二十面体，配不上"天灾"，而且和"十字砸下来"的语言也对不上（十字落地炸出
一颗二十面体，观众会读成两件事）。

现在砸中由事件自己算：半径 26 格的碗形坑（分帧挖）、44 格伤害、
四道推到 80 格外的冲击环、落点原地炸开的十字爆闪。粒子 / 音效 / 镜头
这些共用零件仍然走 `VerdictFeedback`。

### 2. 整条时间线只有一个同步字段

十字大小、火球高度、拖尾长度、颜色、相位——全部是 `age` 的纯函数，
`age` 两端各自累加（与 `CrimsonVowFieldEntity` 同一个做法）。除了"种子"
（决定裂纹形状），没有任何需要每 tick 同步的东西。

### 3. 视线是"轻拉"，不是"锁死"

每帧把当前相机角度朝十字星插值一小部分（`k = 0.075 × fade²`），
玩家的鼠标输入照常生效——想不看就能不看。锁死会读成过场动画，
而且会和鼠标打架。2.5 秒内 fade 退到 0，控制权完整还给玩家。

### 4. 十字**从头到尾都是同一个形状**（实机反馈改的）

第一版到了坠落段会换成火球 + 火球头部——实机截图里能明显看出"天上是一颗
十字，落下来的是一团火"，两件事对不上。

现在坠落段画的仍然是 `uMode = 0` 那颗十字（同一个片元函数、同一套配色，
只是尺寸与颜色随进度变），砸中的第一帧也是落点原地炸开一颗十字，
之后才淡成火球余波。**所以"天上看到的"和"落下来的"永远是同一个东西。**

这一版实机又抓到两个"看起来像另一件事"的元凶，都记在这里：

- **十字是歪的 / 像斜着射下来**：`billboard()` 的 `rotation` 传的是
  `e.getSeed() * 0.12f`，而 seed 是 0~100 万的随机整数 —— 乘出来是几万弧度，
  `cos/sin` 精度早丢了，十字被转到一个任意角度。现在星与拖尾一律传 0，
  要转请用 `Mth.DEG_TO_RAD * 角度`。
- **光柱"平头顶"的硬裁切**：十字的长臂沿轴用的是 `exp(-|x|*2.1)`，
  到四边形边缘还有 0.12 的亮度，于是被四边形的边直接切断。改成
  `(1-|along|)^1.7` 收尖，再乘一道 `smoothstep(1.0, 0.78, r)` 的边缘透明 ——
  臂是收尖的，边框上不会再出现硬边。

### 5. 坠落曲线：一条**连续**的 `1-p⁴`（改过两次）

第一版 `1 - p²` 的末速只有 1.5 格/tick（30 格/秒），从头到尾同一个节奏，
实机反馈"太慢了，末速度应该极快"。

第二版改成两段式（90% 缓降 + 最后 1 秒暴冲），又被反馈"加速太突兀" ——
原因很具体：**两段的加速度在接缝处跳变**，头会先减速到几乎停住、再突然往下掉。

现在是一条连续曲线 `y = H·(1 - p⁴)`：起点速度 0（还挂在天上）、加速度单调增大、
末速 **3 格/tick（60 格/秒）**。没有接缝，所以不会顿一下，但末段仍然是砸下来的。
觉得还不够快就调 `FALL_EXPONENT`（5 会更快、但前段也更"挂机"）。

### 5b. 拖尾：竖直圆柱 + **跟着头走**

屏幕空间的拖影会随镜头转动变形状（这个项目在激光那一招上踩过）。
事件里陨石垂直下落，所以世界空间的竖直圆柱**正好就是它的轨迹**，
不需要任意轴的圆柱。

但圆柱的**远端**放在哪，决定了它看起来动不动：

- 第一版放在 `ground + SIGN_HEIGHT`（十字出现的那个 150 格点）。
  头往下走、尾端不动 ⇒ 整条尾迹被拉成一根挂在天上的光柱，
  流星顺着它下滑 —— 实机反馈"感觉固定在天空中"，就是这个原因。
- 现在远端是 `min(起点, 头 + TRAIL_LENGTH)`（`MeteorEventEntity#trailTop`）：
  尾迹只在头后面保留**最近烧过的一段**，长到 58 格后整段跟着头一起下移；
  同时着色器把衰减从 `pow(1-rel, 1.15)` 提到 `pow(1-rel, 2.4)`，
  再叠一层很长很淡的余烬 `0.10·pow(1-rel, 0.8)` ——
  亮的部分只有头后面三四十格，远端自然散掉，不会再把尾端"钉"在天上。
- 圆柱从"上细下粗"改成**尾端收尖**（尾端半径 = 头部的 0.10 倍）：
  第一版是 1.9 倍张开的"烟囱"，实机反馈"不应该是尾巴尖的吗"。
  现在剪影是一条从头部拖出去、尖端消散的火舌，配合着色器里
  `pow(1-rel, 2.4)` 的衰减，尾端又细又淡。

离屏剖面见 `build/shader-preview/meteor_preview/trail_profile.png`：
从尾端的近黑一路亮到头部的白热，中间是向上跑的湍流条纹。

### 6. 屏效：把**真实画面**重画成漫画分镜（第四版，最终）

需求原话："类似动漫风格的爆炸效果，高对比、有限色阶、二值化/抖动感、
强调轮廓和剪影"，后来补了一句"参考 the-shooting-star-demo 的着色器"。

前三版都在"叠图形"：程序化红黑图案 → 整帧压色阶 → 屏幕空间画星星。
都不是那个味儿。把参考模组的 `composite.fsh` 拆开之后才明白差别：
**它的冲击帧是把真实画面重新画一遍**，不是在世界上面盖东西。核心四步：

| 步 | 做法 | 为什么 |
|---|---|---|
| ① 边缘墨线 | 对场景亮度做 `±1.5px` 的 2 采样差分，梯度 > 0.06~0.18 的地方画黑 | 地形/怪物/十字**自己**被描了边，这才是漫画 |
| ② 局部自适应二值 | 和**周围 8 个方向、半径 0.045 的平均亮度**比，而不是和固定的 0.5 比 | 白闪把整帧推亮时，形状也不会糊成一片 |
| ③ 网点 | 旋转 45° 的点阵（5px），暗处点大、亮处点小 | 中间调的手绘网点 |
| ④ 高光 | 比周围平均亮 0.18 以上直接纯白 | 爆心的过曝 |

配色 = **负片二值**：`frame = mix(paper, ink, two)`，`two = 1` 表示"比周围亮"，
所以**暗部变纸色、亮部变墨色** —— 夜空的暗部于是变成一张白（或橙）纸，
爆炸照亮的部分变成一块黑。参考模组两张截图就是这个极性。

在它之上每 ~80ms 换一次纸色（白 / 橙 / 黑），并且每帧把极性也翻一次
（`lit = mix(two, 1-two, flip)`），于是观感是**大量的颜色反转**；
纸色全黑的那几帧就等于"整帧反相"。

最后 `col = mix(原画面, frame, uIntensity)`，0→1 只用 50ms，保持到 0.45s，
1s 收完。**没有任何绘制的形状**（早几版的十字剪影、冲击环全部删掉）——
画面里出现的每一块黑/白都是**场景自己的**几何。

> 极性踩过一次：写成 `mix(paper, ink, 1-two)` 时夜空直接变纯黑，
> 整个冲击帧等于"屏幕黑一下"，实机反馈"还不如上一版"。现在有注释盯着。

> **采样器不能叫 `Sampler0`。** 那个名字是 Minecraft 核心着色器里**方块图集**
> 的固定名，会随着世界渲染被反复绑成图集 —— 我们手动绑的场景拷贝会被覆盖，
> 采样到的永远是图集。屏幕上的表现就是一片片"橙黑/彩色碎块"（用户形容为
> "奇怪的像素""糊脸"），**不是**二值化噪声。
> 两处都改成了 `SceneTexture`（和项目里 `ScreenTexture` / `DepthTexture`
> 同一个命名习惯）。
>
> 另外 `setSampler(name, X)` 的第二个参数是**纹理 id**，不是单元号；
> 写 0 同样会落到图集上。项目里 `ShockwaveRenderer` / `ApostleSlashWarp`
> 全是传纹理 id 的，照那个写。

> 二值化踩过一次：直接 `step(avg + 0.008, l)` 在夜里会切在**天空的抖动噪点**上，
> 整片夜空被量化成一块块橙/黑碎块（实机截图里那些"奇怪的像素"）。
> 修法三道：① 亮度先做 5 点平滑；② 用**两个模糊量之差**（0.012 / 0.06 半径）
> 而不是单像素；③ 加一道绝对亮度门 `smoothstep(0.03, 0.08, near)` ——
> 比 8% 还暗的表面一律当纸。阈值本身保持很小（0.006），
> 这样一大片亮区仍会整体翻成负片的黑块。

**两个踩过的坑**：

- **中间调必须按绝对亮度判定**。第一版用 `tone`（"比周围亮多少"）当中间调
  掩码，结果一片纯黑的夜空 `l≈avg ⇒ tone=0.5`，整屏被网点铺满，画面变成
  一张红白点阵壁纸。改成 `mid = smoothstep(0.10,0.26,l) * (1-smoothstep(0.55,0.78,l))`。
- **必须拿到场景拷贝**。为此恢复了 `ShockwaveRenderer.doSceneCopy()` 的复用
  （加了 `copySceneForOverlay()` / `sceneTextureForOverlay()` 两个 public 包装），
  在 `AFTER_LEVEL` 拷一次，`uTexel = 1/主RT尺寸` 让网点/墨线按真实像素算。

**扩散中心**（参考的 `Impact` 是 `vec4(strength, mode, centre uv)`）：
`uCenter` 由爆炸点投影得到（相机四元数共轭 → 投影 → NDC → uv），
冲击环用 `d = (uv - uCenter)` 计算，所以是从爆炸点扩散，不是屏幕正中。
落点在相机背后时退回画面那一侧的边缘。

配套的世界侧（只靠屏幕遮罩会觉得"假"）：砸中前 6 tick 在落点放
60→140 格、强度 5 的加法白球，屏幕抖动 `0.85 + 0.15·近距`，FOV 9°，
四道冲击环 + 26 格碗形坑 + 1600 灵魂火。

> 没搬它的后处理管线（bloom / light shafts / 30 多种 Impact 模式），
> 只搬了"整帧重画"这个思路与四步算法。要加 modes，现在有 `uSeed` 和
> `uCenter` 可用，扩起来是加分支的事。
### 6. 实体跟踪距离必须显式放大到 32 区块

`registerNoopEntity` 的默认 `clientTrackingRange` 是 5 区块（80 格）。
这一招的落点可能在 100 格外、十字星还在落点上方 150 格——超了实体就不会
下发，玩家连"事件发生了"都不知道。所以实体走的是手写的
`EntityType.Builder…clientTrackingRange(32)`。

### 7. `uRadius` 是被 UniformCheckTest 抓出来的

第一版 `uRadius` 只声明不使用，被 GLSL 链接器剔除了，而 `.json` 里还写着它——
`ShaderInstance` 在加载时会因为"JSON 声明的 uniform 不存在"而失败，
整支着色器静默变 null。离屏的 `UniformCheckTest` 报出 `MISSING uRadius`
之后删掉了。**新加 uniform 一定要跑一遍这个检查。**

### 还没做 / 已知限制

- **光影包（Oculus/Iris）**：星与拖尾目前直接画在世界 pass，没有像法阵那样
  入队延后回放。pack 激活时颜色会被重新光照，观感会偏。
- **坑的开销**：半径 26 / 深 12 约 1.2 万个方块，按 700/tick 分帧挖完约 18 tick。
  单人测试没问题；服务端带多人时这个量级要按机器再加预算。
- **屏效**：见第四节第 6 条，是覆盖层而不是整帧 posterize。
- **十字星高度 150 格**：需要渲染距离 ≥ 10 区块（远平面 4× 渲染距离），
  低于这个值时星会被远平面裁掉。
- **多次事件**：当前每颗陨石各自独立（会叠加），没有做"同一时间只允许一场"。
