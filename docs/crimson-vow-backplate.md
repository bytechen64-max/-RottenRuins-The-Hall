# 绯红誓约 · 玩家背板（光环）

主手持有 `hall:crimson_vow`（绯红誓约）时，玩家身后浮出一圈**三层誓约纹章**：

```
        外圈：绕圈移动的条带（24 段刻度）
        中圈：六芒星（两个正三角形交叠）
        内圈：正五边形（顶点朝上）
```

它**不含任何贴图** —— 几何是一个 48 段扇形，三层图案全部由片元着色器按**距离场**画出来。
变换、触发、诊断都在客户端，**不发网包、不加 capability**。

---

## 一、最终做法：相机空间里的一块 billboard

一句话：**先在相机空间里把板子摆正，再左乘 `ModelViewMat⁻¹` 抵消管线自己那一步。**

```java
// ① 相机基（世界空间）：right = 视线 × 上
// ② 世界锚点 = 玩家插值位置 + 固定世界高度 + 沿视线方向"远离相机"退 HeadOffset 格
// ③ 锚点 → 相机空间坐标：与相机三轴点积（前方为 −Z）
// ④ 相机空间里"正对镜头"就是单位旋转：+X 屏幕右、+Y 屏幕上、+Z 指向镜头
// ⑤ pose = ModelViewMat⁻¹ × M_view
```

第 ⑤ 步保证的是一条**与约定无关**的恒等式：

```
ModelViewMat × pose = M_view        ⇒   gl_Position = ProjMat × M_view × Position
```

不管 `ModelViewMat` 是单位阵还是"含相机变换的视图矩阵"，最终送进顶点着色器的都是同一个
`M_view`（相机空间里的 billboard）。这一点很重要，因为**这个模组跑在实体渲染通道里，
`ModelViewMat` 实测就是单位阵**（见 §二 ① 的实测输出）。

### 它为什么不会乱跑

| 性质 | 由什么保证 |
| --- | --- |
| 永远在玩家身后，不会转到侧面/身前 | 位置偏移只沿**视线方向**（`+look`），即"从镜头看过去的玩家身后"；偏移量里**没有**玩家朝向，也没有随视角变化的其它量 |
| 永远正对镜头、不会被压成一条棱 | 朝向取相机空间单位旋转，与玩家身体朝向无关 |
| 屏幕上始终贴着玩家的头 | 锚点 = 头部那一点 + `look × HeadOffset`，两点只差一个视线方向的位移 ⇒ **屏幕上重合**（实测偏差 ≤ 0.003 NDC）、深度上恰好远 `HeadOffset` 格 |
| 转视角时位置不跳 | 上式对任意相机朝向都成立：转一圈 NDC 变化 < 0.001（探针），实机 6 个姿态偏差 ≤ 0.003 |

### 调参（`SplendidingConfig`，改完存盘即生效）

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `crimsonBackplateEnabled` | true | 总开关 |
| `crimsonBackplateScale` | 1.3 | **看得见的半径（格）**，1.3 = 直径 2.6 格。矩阵缩放 = 它 ÷ 0.86（0.86 = 着色器 discard 的半径上限，见 `SHADER_VISIBLE_RADIUS`） |
| `crimsonBackplateHeight` | 1.55 | 中心离脚底的高度（格）。≈ 头部后方；调低落到背上 |
| `crimsonBackplateHeadOffset` | 0.65 | 沿视线远离镜头多少格 = "在背后多远"。**必须 > 0** 才能保证永远在玩家身后 |

上一版把动画（呼吸、待机轻摆、格挡缩放、跟镜头偏航）也做进了矩阵，观感是"光环老在动"。
现在**矩阵是死的**：动画只剩"展开/格挡"两个进度，且只喂给着色器（亮度、自转速度）。

## 二、四个真陷阱

### ① 实体通道里 `ModelViewMat` 是**单位阵**，栈顶矩阵已经是**相机空间**

`BufferUploader` 在 flush 时把 `ModelViewMat` 设成 `RenderSystem.getModelViewMatrix()`，
而相机变换早在 `PoseStack` 里做完了：

```
GameRenderer.renderLevel      : poseStack.mulPose(Rz(roll) · Rx(xRot) · Ry(yRot + 180))
EntityRenderDispatcher.render : poseStack.translate(实体位置 + renderOffset − 相机位置)
LivingEntityRenderer.render   : × Ry(180 − bodyRot) × S(−1,−1,1) × S(0.9375) × T(0,−1.501,0)
```

所以 **RenderLayer 拿到的那张栈顶矩阵 = 相机空间**，把 **`playerPos − camPos`（相机相对世界坐标）
写进平移列就错了一次**：那是世界向量，被当成相机空间坐标用，等于相机旋转被乘两次。
症状正是"一转视角，光环从我背后飞到侧面、再飞到脸前"。

数值复现（`docs/probe/BackplateProbe.java`，固定玩家、相机绕一圈）：

```
yaw=  0  旧版 NDC=( -0.00,  0.55) w=  3.76 | 新版 NDC=( 0.00,-0.02)
yaw= 45  旧版 NDC=(  0.80,  0.77) w=  2.66 | 新版 NDC=(-0.00,-0.02)
yaw= 90  旧版 NDC=(   NaN,   NaN) w=  0.00 | 新版 NDC=( 0.00,-0.02)   ← 正好落在相机平面上
yaw=135  旧版 NDC=( -0.80, -0.77) w= -2.66 | 新版 NDC=( 0.00,-0.02)   ← 掉到相机背后
yaw=180  旧版 NDC=(  0.00, -0.55) w= -3.76 | 新版 NDC=( 0.00,-0.02)
```

### ② `RenderSystem.getModelViewMatrix()` 不能当"世界→相机"用

它读的是渲染管线当前那份 `ModelViewMat`，实体通道里是单位阵 —— 拿世界坐标喂进去会原样吐出来。
上一版据此算出的"环在屏幕 (x, y)"全是假的（日志里 `★ 不在预期位置` 就是这么来的）。
它只有一个正确用法：和 `ProjMat` 一起代入 `Proj × MV × pose × 顶点` 算**屏幕 NDC**
（这正是 GPU 要做的），诊断里就是这么用的。

### ③ 偏移量里不能出现玩家朝向

`yaw` / `bodyRot` / `headRot` 都是**世界空间**的朝向。一旦拿它们算位置，
相机绕到侧面时"光环的世界位置"没变、但相对镜头的方向变了 ⇒ 从背后跑到侧面；
若再用它做朝向，板面还会侧对镜头被压成一条棱。
现在位置只由「玩家位置 + 世界高度 + 视线方向」决定，朝向只由相机决定，两者互不污染。

### ④ 后退方向要用**完整**的视线向量，不能只取水平分量

"沿视线后退"如果写成 `(look.x, 0, look.z) × HeadOffset`，那两条不变量
（环心与头部同屏、恰好远 `HeadOffset` 格）就只在镜头放平时成立，一俯仰就退化成
`HeadOffset × cos²(pitch)`：45° 时深度余量从 0.65 掉到 **0.325**（身体会切穿光环），
屏位也偏出 **NDC 0.16**。这个错误在自己的数值探针里看不出来（探针写的是完整向量），
是实机诊断在俯仰姿态下打出来的 —— 所以两边都要跑。

---

## 三、不要做的事（五条）

1. 不要把世界坐标（含 `playerPos − camPos`）写进栈顶矩阵的平移列 —— 那是相机空间。
2. 不要用 `RenderSystem.getModelViewMatrix()` 把世界坐标转成相机坐标。
3. 不要用 `yaw` / `bodyRot` / `headRot` 算位置或朝向。
4. 不要在覆盖矩阵之后再 `translate` 做局部平移 —— 平移方向会退化成相机空间的轴。
5. 不要在矩阵里做呼吸/待机摆动/跟镜头偏航：用户要的是一块**不动**的牌子。

## 四、三层图案怎么画

几何刻意做得极简：**一个 48 段的扇形**（圆心 + 一圈边缘点，单位平面上），
顶点只带两个数：`UV0.x = 半径`（1.0 = 内切圆，√2 = 方框角）、`UV0.y = 方位角`（裸弧度，
接缝处连续，角频率交给片元的 `fract()`）。图案全在片元里按**距离场**算：

| 层 | 半径范围 | 画法 |
| --- | --- | --- |
| 正五边形 | 中心 ~ 0.60 | `polygonSdf(theta, r, 5, −π/2, 0.34)`（旋转量取 `−π/2` 让顶点朝上） |
| 六芒星 | 0.60 ~ 0.80 | 两个 `polygonSdf(..., 3, ...)` 交叠（+π/2 与 −π/2），取 `min(abs())` |
| 条带 | 0.80 之外 | 环带 + 沿角向跑的相位 + 24 段刻度 |

- 线宽统一用 `fwidth()` 归一化（屏幕空间恒定粗细），否则近看一根粗管子、远看整条消失。
  另有 `PixelWidth`（Java 侧每帧上传 `1 / 窗口物理像素宽`）作为托底 ——
  极细的线上 `fwidth` 会趋于 0，只靠它会让线在远处整体消失。
- `r > GLOW_OUTER + 0.02` 直接 `discard` —— 几何是方框、图案是圆的，不丢会露出四个方角。
  **`GLOW_OUTER` 与 Rig 里的 `SHADER_VISIBLE_RADIUS = 0.86` 必须同步**
  （0.86 是 Rig 里矩阵缩放的换算基准：`Scale` 是"看得见的半径"，除以它才是矩阵缩放）。

### 内饼的 Voronoi 方块纹（D）

内饼不再是空的，填了一层极淡的**三角形度量 Voronoi**，与本体那把剑的 cosmic 图案同源
（`blockDist` 取 `L∞` 而不是欧氏距离，格子才会是方块而不是圆斑）。
它的 alpha 上限压到 **0.30**，所以读起来是"底色质感"而不是"一块板"。

> **曾经的 bug**：这块填充原先是 `(1 - smoothstep(max(triUp, triDown))) * 0.10`，
> 而 `max(triUp, triDown)` 的**负值区是两个三角形的交集** —— 也就是半径 0.62 的实心六边形，
> 比外层过渡带还大。于是它被 `mix` 铺满整个内圈，成了画面里那层灰白奶膜，
> 把五边形和六芒星全糊掉了。现在改成只保留星形轮廓外缘的极淡内描边（`HEX_INNER_STROKE`）。
>
> 同一个函数里 `inner` 的正负也写反了：`polygonSdf` 是 **sdf < 0 才在内部**，
> 而旧代码的 `smoothstep(0, lw, sdf)` 取的是外部。

### 外发光（E）

条带之外一圈柔晕，内外两端都做软过渡（硬边会读成"又一个圆环"而不是光晕），
强度走二次衰减，叠一个很慢的呼吸。它是**可以压掉的**：`GLOW_STRENGTH = 0` 即关闭。

### 各层强度旋钮（都在 `.fsh` 顶部，改完 `F3+T` 重载资源即生效）

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `FILL_BLOCK_STRENGTH` | 0.42 | 内饼 Voronoi 强度，设 0 退回纯暗底 |
| `FILL_BLOCK_FREQ` / `FILL_BLOCK_SPIN` | 3.1 / 0.004 | 方块纹密度与流动速度 |
| `GLOW_STRENGTH` / `GLOW_OUTER` / `GLOW_INNER` | 0.30 / 1.16 / 0.94 | 外发光的强度与半径范围 |
| `GLOW_PULSE_SPEED` | 0.030 | 外发光呼吸速度 |
| `HEX_INNER_STROKE` | 0.16 | 六芒星内描边强度 |
| `VowColor` / `AccentColor` | 深绯红 / 雾粉紫 | 径向色带的**两端**（F）；片元按归一化半径插值 |

## 五、两遍绘制与 flush 顺序

| 顺序 | 内容 | RenderType | 混合 |
| --- | --- | --- | --- |
| ① | 底：板面 + 三层图案的暗部 | `crimson_backplate` | 普通 alpha + 写深度 + 剔除背面 |
| ② | 亮：五边形顶点、六芒星角、条带 | `crimson_backplate_glow` | 加法 + 不写深度 |

**两遍之间必须 `endBatch`。** `Uniform.set()` 只是把值记在 `Uniform` 对象上，
真正上传发生在 `ShaderInstance.apply()`（也就是 flush）时。攒在一起再 flush，
后一遍设的值会覆盖前一遍 —— 症状是"底层也变成了发光层的颜色"。

几何只发一份 144 顶点（`POSITION_TEX`，每条 20 字节 ≈ 2.9KB）。
billboard 永远正对镜头，背面看不到，所以底那一遍开**背面剔除**是安全的：
探针里把扇形第一条三角形投到 NDC 算有符号面积 = **+0.0157 > 0**（逆时针 = 正面）。

再复刻实体渲染管线扫描 40 个相机姿态，最后给出旧版对照。当前**全绿**：

`run/config/hall/SplendidingConfig.json5` 里把 `"debug"` 改成 `true`，

环心 NDC 在全部姿态下都是 `|x| < 0.001`、`|y| < 0.02`，`w ≈ 4.2 ~ 4.7`：

- `覆盖前栈顶平移列 == 预测(相机空间)` ⇒ 栈顶确实是相机空间（陷阱 ① 的直接证据）；

- `Z 列 = (0,0,1)` ⇒ 板面正对镜头；
- `环比头部远 0.650 格` 且 `环心与头部同屏` ⇒ 永远在玩家身后同一个屏位。

## 八、已知边界

- **第三人称专属**：原版第一人称不渲染本地玩家实体，所以这个层根本不会被调用。
- **相机被墙挤到不足 1 格时**光环会整个被近裁剪面切掉而消失（整块板都在相机前方
  不足 0.05 格处）。调小 `HeadOffset` 可缓解。
- **游泳 / 鞘翅滑翔时不画**：这两种姿态下身体横过来，"头部后方"这个锚点没有意义
  （见 `shouldRender`）。
- **光影包**下走实体通道、吃 GBuffer，不参与后处理泛光。
