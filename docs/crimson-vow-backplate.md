# 绯红誓约 · 玩家背板（血月誓约纹章）

主手持有 `hall:crimson_vow`（绯红誓约）时，玩家身后浮出一枚**血月誓约纹章**：

```
        ╱╲   ╱╲╱╲   ╱╲          冠冕：56 条细射线 + 头顶五瓣冠 + 七根长刺
      ╱   ╲ ╱    ╲ ╱   ╲
     │  ┌──────────────┐  │      日蚀边（血月轮廓，全图最亮的连续线）
     │  │  ▓▓ 符文带 ▓▓ │  │      符文带：20 格程序化"誓约文字"
     │  │   ┌──────┐   │  │      内轨环 / 刻度环 / 内封印环
     │  │   │ 血月 │   │  │      血月盘体：暗红月海 + 血纹（衬底）
     │  │   └──────┘   │  │
     │  └──────────────┘  │
      ╲   ╱ ╲        ╱   ╱      余烬：绕外缘缓慢外漂的星点
        ╲╱   ╲╱╲╱   ╲╱
```

它**不含任何贴图** —— 几何是一个 48 段扇形，全部图案由片元着色器按
**极坐标 + 距离场**现算。变换、触发、诊断都在客户端，**不发网包、不加 capability**。

> 这一版是重做。上一版是「正五边形 + 六芒星 + 外圈条带」三层互不相关的图形，
> 实机画面糊成一团粉白甜甜圈，用户反馈"形状莫名其妙"。两个真凶见 §三。

---

## 一、为什么是"血月 + 冠冕"

背板在第三人称下**会被玩家自己的身体挡住中下部约 1/3**（它在玩家身后 0.65 格，
身体在它前面）。所以"画一个完整的圆"这条路线天生不成立：玩家永远只能看到
一个缺了下半的圆环，任何放在正中心的图案都被头和躯干盖住。

日蚀的构图天然解决这件事：

- 玩家正好站在**暗盘**中心 —— 被挡住的核心区域本来就不承载信息；
- 露出来的是**亮边、两侧符文与头顶的冠**，这三样都在剪影之外；
- 头顶的冠是整块板**唯一的非对称元素**，把"誓约之冠"点在玩家头上；
- 暗盘同时是一块"遮住身后世界"的深色衬底，给亮部提供对比度。

所以设计不是"在一个圆里塞图案"，而是"让玩家的剪影成为纹章的一部分"。

### 放射层次（片元里的归一化半径 `u`，1.0 = 可见外缘）

| u | 元素 | 作用 |
| --- | --- | --- |
| 0.00 ~ 0.22 | 誓约之心（柔光） | 被头部挡住，只从头顶溢出一点光 |
| 0.33 | **内封印环** | 正好框住头颈的一圈光环 |
| 0.37 ~ 0.41 | 刻度环（24 枚细刻，反向自转） | 内环与外环之间的过渡 |
| 0.462 | 内轨环 + 40 枚细刻 | 填住"封印环 → 符文带"之间那一圈 |
| 0.50 ~ 0.66 | **符文带**（20 格"誓约文字"） | 主细节层；每格 3 笔 + 1 点，由 hash 决定 |
| 0.70 | 轨环 + 72 枚细刻 | 符文带与日蚀边之间的呼吸带 |
| 0.78 | **日蚀边**（血月轮廓） | 全图最亮的连续线，带一圈扫过边缘的亮弧 |
| 0.78 ~ 1.00 | **冠冕** | 56 条细射线 + 头顶五瓣冠 + 七根长刺 + 余烬 |

### 心誓（心跳）

`Time` 是 **tick**（20 tick/s）。片元用
`period = mix(19, 11.5, Block)` 做心跳周期：

- 常态约 0.95 Hz 的缓慢心跳，驱动边缘亮度、冠冕、符文、内环与一圈
  从中心向外推的**誓约波**；
- 举剑格挡（`Block → 1`）时心跳加快到约 1.7 Hz、幅度变大，整块纹章"烧起来"；
- 展开（`Reveal 0→1`）时整块纹章从 0.55 倍长到 1 倍并点亮。

## 二、几何与顶点约定（这一版改了）

几何仍是 `CrimsonVowBackplateMesh` 里的一个 **48 段扇形**（圆心 + 一圈边缘点），
`POSITION_TEX`，`z = 0`。但 **`UV0` 的语义换了**：

| | 上一版 | 这一版 |
| --- | --- | --- |
| `UV0` | `(r, θ)`，片元直接读 | **单位平面局部坐标 `(x, y)`** |
| 半径 | 直接取 `UV0.x` | `r = length(UV0)` |
| 角度 | 直接取 `UV0.y` | `θ = atan(UV0.y, UV0.x)` |

原因见 §三 ②。三角形成员的 `UV0 = (x, y)` 与 `Position.xy` 同值，CPU 侧只是多写
两个 float，片元多一次 `length + atan`。

## 三、这一版修掉的两个真 bug

### ① 线宽被 `PixelWidth * 260` 托底成 0.13~0.2 UV —— 图案比线还细

上一版所有线的半宽是：

```glsl
float lineAA(float sdf) {
    return fwidth(sdf) * 1.6 + PixelWidth * 260.0 + 0.004;
}
```

`PixelWidth = 1 / 窗口像素宽`，所以第二项在 1920 宽窗口下是 **0.135 UV**。而图案的
半径尺度只有 0.6~0.8 UV —— 也就是说**线比图案本身还粗 3~5 倍**，五边形、六芒星、
刻度全部被糊成一片粉白。离屏图里一眼就能确认：整块只剩一个发白甜甜圈。

那个 `* 260` 的原始意图是"`fwidth` 在极细线上会趋于 0，需要托底"，但**前提是错的**：
`fwidth` 是"一个像素在图案空间里的跨度"，线再细它也不会归零，反而正是抗锯齿
应有的宽度。所以这一版线宽统一写成：

```glsl
float lw = max(fwidth(u) * 1.35, 0.0016);   // 屏幕恒定 ~1.5px，另有极细下限
```

### ② 扇形顶点的 `θ` 线性插值不是真角度 —— 48 条三角形边会撕出"花瓣"

上一版把 `UV0 = (r, θ)` 直接交给片元插值。问题在于扇形三角形里**圆心那一点的角度
是逐三角形各不相同的**（取的是该段起点 `thetaA`）：

```
三角形 s   : 圆心 θ=θ_s       边缘 A θ=θ_s   边缘 B θ=θ_{s+1}
三角形 s+1 : 圆心 θ=θ_{s+1}   边缘 A θ=θ_{s+1} 边缘 B θ=θ_{s+2}
```

两条三角形共享的那条半径边上，两侧对 `θ` 的插值结果**不相等**（左侧从 `θ_s` 插到
`θ_{s+1}`，右侧恒为 `θ_{s+1}`）。48 段就有 48 次角度跳变 —— 于是所有依赖 `θ` 的
图案（符文带、刻度环、冠冕射线）都被撕成一圈"花瓣/扇叶"。

位置是线性插值正确的量，所以修法是：**传局部坐标 `(x, y)`，角度在片元里现算**。

> 这条与 `DifficultySigilMesh` 里"顶点只带相位、角度在片元算"是同一条教训，
> 只是那边踩的是 `0 / 2π` 接缝，这边踩的是三角形内部的角度扭曲。

## 四、两遍绘制：同一着色器，靠 `GlowPass` 分支

| 顺序 | 内容 | RenderType | 混合 | 深度 |
| --- | --- | --- | --- | --- |
| ① | 底：血月盘体 + 月海/血纹 + 蚀刻暗纹 | `crimson_backplate` | 普通 alpha | 测试 + 写 |
| ② | 亮：日蚀边 / 封印环 / 符文 / 冠冕 / 余烬 / 心誓波 | `crimson_backplate_glow` | 加法（`SRC_ALPHA, ONE`） | 测试、不写 |

`GlowPass` 是这一版新增的 uniform：

- `0` → 底遍：只输出暗部结构，`alpha` 走普通混合；
- `1` → 亮遍：只输出自发光，`alpha = 1`（颜色自己就是强度，加法叠加），
  亮度低于阈值的像素直接 `discard`。

**两遍之间必须 `endBatch`**：`Uniform.set()` 只是把值记在 `Uniform` 对象上，真正的
上传发生在 `ShaderInstance.apply()`（也就是 flush）时。攒在一起再 flush，后一遍设的
值会覆盖前一遍 —— 症状是"底层也变成了发光层的颜色"。这与 `MaskLayerRenderer`
类注释记的是同一条。

几何只发一份 144 顶点（`POSITION_TEX`，每条 20 字节 ≈ 2.9KB）。
底板面永远正对镜头，背面永远看不到，所以底遍开**背面剔除**是安全的。

## 五、变换：相机空间里的一块 billboard（沿用上一版，未改）

一句话：**先在相机空间里把板子摆正，再左乘 `ModelViewMat⁻¹` 抵消管线自己那一步。**

```java
// ① 相机基（世界空间）：right = 视线 × 上
// ② 世界锚点 = 玩家插值位置 + 固定世界高度 + 沿视线方向"远离相机"退 HeadOffset 格
// ③ 锚点 → 相机空间坐标：与相机三轴点积（前方为 −Z）
// ④ 相机空间里"正对镜头"就是单位旋转：+X 屏幕右、+Y 屏幕上、+Z 指向镜头
// ⑤ pose = ModelViewMat⁻¹ × M_view
```

第 ⑤ 步保证的是一条**与约定无关**的恒等式：

```
ModelViewMat × pose = M_view        ⇒   gl_Position = ProjMat × M_view × Position
```

不管 `ModelViewMat` 是单位阵还是"含相机变换的视图矩阵"，最终送进顶点着色器的都是
同一个 `M_view`（相机空间里的 billboard）。实体通道里 `ModelViewMat` 实测就是单位阵。

### 它为什么不会乱跑

| 性质 | 由什么保证 |
| --- | --- |
| 永远在玩家身后，不会转到侧面/身前 | 位置偏移只沿**视线方向**（`+look`），偏移量里**没有**玩家朝向 |
| 永远正对镜头、不会被压成一条棱 | 朝向取相机空间单位旋转，与玩家身体朝向无关 |
| 屏幕上始终贴着玩家的头 | 锚点 = 头部那一点 + `look × HeadOffset`，两点只差一个视线方向位移 ⇒ 屏幕上重合 |
| 转视角时位置不跳 | 上式对任意相机朝向都成立 |

### 调参（`SplendidingConfig`，改完存盘即生效）

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `crimsonBackplateEnabled` | true | 总开关 |
| `crimsonBackplateScale` | **1.5** | **看得见的外缘半径（格）**，1.5 = 直径 3 格。矩阵缩放 = 它 ÷ 0.86 |
| `crimsonBackplateHeight` | 1.55 | 中心离脚底的高度（格）≈ 眼睛高度 |
| `crimsonBackplateHeadOffset` | 0.65 | 沿视线远离镜头多少格。**必须 > 0** |

> 尺寸从 1.3 提到 1.5 是这次重做的一部分：旧版 1.3 时符文带正好落在"玩家肩宽之内"，
> 被手臂吃掉；1.5 让符文带整圈露出来，但还没到"盖住半个屏幕"的程度。
> 改这个值只需存盘，不需要重编译。

## 六、图案怎么画（片元结构）

全部是极坐标 + 距离场，没有贴图、没有采样：

- **线**：`gauss(d, w)`（柔和，用于环/光晕）与 `line(d, w)`（硬一点，用于符文笔画）。
- **符文带**：把角度切成 20 格，每格用 `hash11(cell)` 生成竖笔位置/高度、横笔位置/
  长度、底笔开关、斜笔开关与一颗星点 —— 远看是一条"文字带"，近看每格都不同。
  每格还有极慢的明灭相位，读起来像被逐字点亮。
- **日蚀边**：一条高斯线，半径上叠加 `sin(5θ)`、`sin(13θ)` 的微小起伏（不是数学圆），
  再叠一段绕圈奔跑的亮弧（`pow(cos(θ - t·0.03), 14)`）。
- **冠冕**：56 条细射线（每格长度/亮度由 hash 决定，头顶方向自动更长）
  + 头顶五瓣宽底尖顶的"火舌" + 七根穿插其间的细长刺。
- **余烬**：48 格各一颗，相位错开、缓慢外漂并衰减。
- **血月盘体**：两层 fBm 做月海 + 一层 ridged fBm（`1-|2f-1|` 的尖脊）做血纹；
  靠近边缘抬一圈暗红，心跳时整盘透出血色。
- **心誓波**：`fract(beatPhase)` 驱动一圈从中心往外推的环，被盘体压住、只在
  暗盘上可见。

### 各层强度旋钮（都在 `.fsh` 顶部，改完 `F3+T` 重载资源即生效）

| 常量 | 默认 | 作用 |
| --- | --- | --- |
| `R_OUT` | 0.86 | 可见外缘（**必须与 `CrimsonVowBackplateRig.SHADER_VISIBLE_RADIUS` 同步**） |
| `U_LIMB` | 0.780 | 日蚀边半径 |
| `U_RUNE_C` / `U_RUNE_H` | 0.580 / 0.085 | 符文带中心/半高 |
| `U_SEAL` | 0.330 | 内封印环半径 |
| `RUNE_CELLS` | 20 | 符文格数（越小字越大） |
| `RAY_CELLS` | 56 | 冠冕细射线数 |
| `period = mix(19, 11.5, Block)` | | 心跳周期（tick/拍）：格挡时加快 |

## 九、已知边界

- **第三人称专属**：原版第一人称不渲染本地玩家实体，所以这个层根本不会被调用。
- **相机被墙挤到不足 1 格时**纹章会整个被近裁剪面切掉而消失。
- **游泳 / 鞘翅滑翔时不画**：这两种姿态下身体横过来，"头部后方"这个锚点没有意义
  （见 `shouldRender`）。
- **光影包**下走实体通道、吃 GBuffer，不参与后处理泛光。
- 暗盘是半透明（alpha ≈ 0.76~0.86）且**写深度**的：它会遮住身后的世界，
  这是"日蚀"的表现需要，但也意味着正对它背后的半透明物体可能被裁掉。
